## 승인된 상주 MCP 관리

개발 Core 프로파일은 명시적 plugin 클래스·custom hook·provider·reporter·check factory·
capability alias를 가진 고정 소유자를 사용할 수 있습니다. 동일한 `PluginManager`
수명주기·확장 포트를 호출하며 Python을 받거나 다른 worker의 binding 파일을 변경하지
않습니다. 모든 조회·효과에 별도 운영자 승인이 필요합니다.
[MCP 계약](../guides/mcp.md#binding-기반-core-보안plugin-관리)을 참조하세요.


## 같은 manager의 네이티브 실행 (개발 소스)

`PluginManager.validate(check_factories, data=None, asset_provider=None, name="plugin-suite", result_format="summary", parallel=False, max_workers=None, pushdown=None)`는 등록된 `CheckSpecFactory` 또는 기존 네이티브 Validator 등록을 kernel suite로 컴파일하고 자료 또는 하나의 네이티브 `DataAssetProvider`로 실행합니다. 반환한 `PluginValidationResult`는 `.run`, 상세 `.hooks`, `.hooks_failed`를 제공합니다. context·workspace를 암묵적으로 저장하지 않습니다. `validate_async`는 데코레이터로 감싼 async handler까지 기다리며 provider·kernel 작업은 호출한 스레드에서 수행합니다. 동기 버전은 실행 중 event loop에서 효과 전에 거부합니다.

`render(reporter_name, run)`·`render_async`는 등록된 v3 reporter 클래스·생성자·구성된 객체에 canonical `ValidationRunResult`를 전달하고 텍스트·bytes인 `PluginRenderResult.content`와 hook 결과를 반환합니다. 구조적 v3 reporter도 지원하며 `ValidationReporter` 상속은 필수가 아닙니다. 구성된 인스턴스는 manager 내부에 유지하고 생성자는 전역 reporter factory 등록도 유지합니다.

`HookManager.trigger_detailed`·`trigger_detailed_async`는 type·source·success·result·선택적 오류 종류를 담은 `HookExecutionResult`를 반환합니다. 성공한 None과 실패를 구분하며 예외 본문을 로그·결과에 넣지 않습니다. 기존 trigger는 결과 목록을 유지합니다. 상세 동기 호출은 awaitable handler를 명시적으로 거부하고 coroutine을 누출하지 않으며 비동기 호출은 실제 awaitable을 기다립니다. 신뢰된 `set_execution_guard`는 각 hook 직전에 검사하며 manager 흐름은 provider·factory·report 직전에도 확인합니다. 거부된 unload hook 때문에 소유 자원의 teardown·제거를 생략하지 않습니다.

검증 hook의 `checks`·`validators`는 불변 `CheckSpec` 의도이고 issue hook은 대응하는 check 의도를 받습니다. hook 실패는 검증을 중단하지 않는 별도 결과입니다. provider는 연결과 최종 종료를 소유합니다. [Core MCP plugin 계약](../guides/mcp.md)은 승인된 동일 소유자에서 이 흐름·표준 결과 내보내기·크기 제한 artifact·입력 권한 수명을 제공합니다. 다른 worker registry의 암묵적 변경·임의 import·원격 실서비스 검증을 추가하지 않습니다.


`unregister_check_factory`·`unregister_data_asset_provider`·`unregister_reporter`·`unregister_capability`는 manager의 안정 port 조회를 제거하며 자원 소유권을 추정하거나 공유 provider를 닫지 않습니다. 전역 reporter 생성자는 현재 객체가 이 manager가 등록한 객체와 동일할 때만 제거합니다. `truthound.reporters.unregister_reporter(name, expected_constructor=...)`도 같은 원자적 소유권 검사를 제공합니다. 구성된 reporter 인스턴스는 manager 내부에 유지합니다. 잘못된 reporter 계약 metadata는 기존 binding을 바꾸기 전에 거부합니다.

`unload_plugin(name,detailed=True)`의 `PluginCleanupResult`는 비활성화·teardown 완료·registry 제거·unload hook 실패·예외 종류를 보존합니다. `.success`는 네이티브 callback 완료를 나타내며 외부 provider의 해제 확인은 아닙니다. 기본 호출은 None 호환성을 유지하고 guard 거부는 cleanup 뒤 전파합니다. unregister·teardown 예외 본문은 로그에 넣지 않으며 unload hook이 거부되어도 teardown을 시도합니다. [Core MCP](../guides/mcp.md)는 registry 제거를 전체 cleanup 성공으로 바꾸지 않고 실패 receipt를 보존합니다.
